Zexel Pay

Designing for 3 User Types with Competing Needs

Payment platform for influencer marketing collaborations

Role Solo UX/UI Designer
Timeline 6 months (March - Sept)
Challenge Multi-user platform design
1

Problem

Zexel Pay began as a fintech solution to streamline payments between brands, agencies, and influencers for marketing collaborations. The initial concept focused on a single user interface where companies would manually enter payment details for each influencer.

As stakeholders wanted to add more functionality, a critical UX problem emerged: cramming features for three fundamentally different user types into one interface would create overwhelming noise and confusion.

The Core Tension

  • Companies: Process bulk payments efficiently, reduce administrative burden (consolidate thousands of invoices)
  • Influencers: Get paid quickly with minimal platform time
  • Admins: Oversight of entire payment flow between both parties

Risk if Unresolved

A cluttered platform where each user type would be distracted by irrelevant features, leading to confusion, errors, and abandonment. Users would be forced to navigate through functionality that didn't align with their jobs-to-be-done.

My strategic insight: I identified early that forcing all functionality into one interface wouldn't work. I proposed separating the experience based on each user's primary job-to-be-done: sending money vs. receiving money.
2

Process

Discovery & Requirements Gathering

Worked with startup team where requirements were unclear. Spent significant time in 3-hour stakeholder meetings filtering valuable insights from noise. Collaborated across product, development, and marketing teams to extract needs.

Strategic Pivot: Multiple User Profiles

Advocated for separating user experiences rather than creating a bloated universal interface. Proposed at least two distinct types based on jobs-to-be-done: those sending money and those receiving it. Later added admin super-user profile.

Information Architecture

Created extensive IA maps and user flow diagrams. Defined the three profiles with specific task-focused interfaces. Designed navigation and feature sets aligned to each user's goals.

Design & Iteration

Developed wireframes and prototypes while learning Figma on the job. Faced resistance from stakeholders who didn't understand design process—educated on wireframe-to-prototype progression. Iterated based on cross-functional feedback.

Usability Testing & Refinement

Conducted usability tests to identify navigation issues and programming errors. Made iterative improvements to reduce friction and clarify user flows.

Timeline: First designs delivered within one month. First stable version delivered in 6 months.

3

Solution: Three Distinct User Profiles

🏢

Company Profile

"I need to process bulk payments efficiently"

  • CSV upload for bulk payments
  • Campaign-based batch management
  • Prepare batches over time, approve when ready
  • Single consolidated invoice
  • Payment status monitoring
✨

Influencer Profile

"I want to get paid quickly and easily"

  • Simple payment request creation
  • Invoice upload functionality
  • Minimal, streamlined interface
  • Clear payment status visibility
  • Fast, low-friction experience
⚙️

Admin Profile

"I need oversight of the entire payment flow"

  • Combined company + influencer capabilities
  • Full system permissions
  • Cross-user visibility
  • Payment flow management
  • Issue resolution tools

By separating these experiences, each user type saw only the features relevant to their tasks, dramatically reducing cognitive load and improving usability.

Outcome & Impact

Delivered: Complete user flows for three profiles, full screen designs, reusable component library, component specifications, and brand implementation across platform.

The platform launched and is still in operation. While final design iterations weren't fully implemented due to team restructuring, the improvements that were implemented showed measurable results:

Reduced Errors

Significant reduction in human error through clearer flows and better-grouped concepts

Clearer Flows

Users could anticipate action outcomes and understand available actions

Better Navigation

Improved menu structure with task-based conceptual grouping

Enhanced Copy

Contextual help for complex terminology, translated platform

Positive feedback from users, developers, and stakeholders on all implemented improvements.

6

Lessons Learned

About Multi-User Design

  • Jobs-to-be-done clarity is essential—each user needs interfaces aligned with specific tasks, not a feature buffet
  • Find connection points where design creates consistent experiences while respecting different needs
  • Design for reusability with shared components and user-specific variations
  • Speak each user's language in copy, terminology, and interface patterns
  • Listen beneath the surface—users express symptoms, not root needs

About Product Design Process

  • Design balances competing interests: business goals, technical constraints, and user needs
  • Translation between teams is as important as visual design work
  • Educating stakeholders on design process is part of the job

What I'd Do Differently

  • Trust professional judgment earlier and fight harder for user-centered choices
  • Learn metrics tools (Analytics, Hotjar) sooner to support decisions with evidence
  • Spend less time polishing early concepts—trust the iterative process

Personal Discoveries

  • I have both creative and analytical thinking—can envision ambitious solutions and break them into realistic steps
  • I see both details and big picture, and how they interact
  • I'm resilient—rejection stings but I consistently return with stronger ideas
  • I can lead, communicate persuasively, and advocate for change against resistance
